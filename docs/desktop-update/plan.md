# План поставки с ручной приёмкой после каждого шага

База `release/nov-16`, коммит `666a028`. Отдельная рабочая ветка `feat/update`. Сначала проходим шаги 1–4 на Mac, затем 1–3 и 5 на Windows. Шаг 6 закрывается отдельно на каждой ОС. Перед написанием кода команда даёт правила реализации. Каждый следующий шаг начинается после демонстрации предыдущего на установленной сборке.

**Подготовка.** Установить A в отдельный тестовый каталог, записать её версию и путь. Подготовить B с тем же контрактом форматов, отдельный config и два Data Root. В первом создать заметку с узнаваемым текстом, записать Corpora ID, ID агента и версию схемы. Второй каталог пуст. При повторном запуске указывать второй root и отдельный config явно. Использовать локальную раздачу с журналом запросов, ручной паузой после первых 256 КиБ и командой продолжения. Такой стенд — первый артефакт шага 1; автоматические свидетельства из `ba3342d` служат эталоном для сравнения.

| Шаг и поставляемый результат | Что делаем руками | Ожидаемое наблюдение |
|---|---|---|
| **1. Найти B и показать кнопку.** Проверка метаданных и предложение в доверенном shell. | Открыть A в Workspace, затем в Welcome. Посмотреть версию на кнопке, закрыть и снова открыть A. На контрольном прогоне сменить предложение B на C перед нажатием. | Без клика в журнале только метаданные; установлена A. Если выбранная B недоступна, к C требуется новый клик. Для гостевой страницы действие установки недоступно. |
| **2. Безопасно остановить backend.** Новый протокол Busy/остановка и наблюдение выхода. | Поочерёдно запустить задачу, оставить принятую очередь и начать работу в локальной дочерней Corpora. Нажать кнопку. Затем закончить работу и повторить в простое. В отдельном прогоне тестовым переключателем задержать подтверждение остановки. | Busy возвращается сразу, работа завершается, запросов за пакетом нет. В простое виден штатный выход и пустая группа процессов/job. Потеря подтверждения не запускает загрузку или установщик. На этом шаге результатом служит зафиксированная готовность к handoff. |
| **3. Защитить установку независимо от корней.** Разделяемое владение при работе, исключительное при замене. | Открыть одну копию A на двух уже подготовленных корнях. Попробовать обновить первую, пока второй пользуется установкой; закрыть его и повторить. Отдельно проверить штатный прямой запуск packaged backend при активном handoff с пустым корнем. | До обновления обе сессии работают. При живом втором владельце установка отклонена, второй workspace доступен. После передачи владения обычный запуск и прямой packaged backend оставляют пустой корень пустым. |
| **4. Закончить macOS A→B.** Подписанный помощник и Sparkle в поставке. | Сделать обычное обновление без вмешательства. На свежей A повторить с паузой раздачи. После подтверждения выхода backend завершить только PID shell A в Activity Monitor. Запустить ту же A со вторым корнем, осмотреть каталог, снять паузу. | До снятия паузы на диске A, второй backend не появился. Потом установлена ровно предложенная B, одно рабочее окно на первом корне, та же заметка и идентификаторы. Сохранить запрос DMG, журнал Sparkle и подпись установленной B. |
| **5. Закончить Windows A→B.** Проверка издателя, существующий per-user Inno и обработка его результата. | Под обычной учётной записью повторить обычный и прерванный сценарии шага 4. Завершать только PID shell A в Диспетчере задач. Посмотреть InstallLocation и журнал Inno. Отдельно предложить тестовый пакет с неподходящим издателем. | Положительный прогон даёт один запрос EXE и один запуск B, код Inno 0, прежний путь установки и первый workspace. Пакет с чужим издателем отклонён до запуска Setup. |
| **6. Восстановление и выпуск.** UI ошибки, ремонт, опубликованная пара A/B. | Оборвать передачу до запуска установщика, проверить возврат A. На одноразовой установке проиграть неопределённый исход после начала замены, открыть приложение и выполнить Repair. Отдельно проверить Windows reboot-required и поведение общей macOS-копии без подтверждённой эксклюзивности. В конце повторить обычный путь с итоговыми подписанными пакетами. | Определённый отказ оставляет доступной целую A. При неизвестном исходе рабочий backend ждёт подтверждения или ремонта. Windows сообщает о перезагрузке; общая Mac-копия предлагает ручной путь. После успеха B открывает исходную заметку и Corpora. |

**Что записываем после демонстрации.** Дата, ОС и права пользователя; A/B и хеши пакетов; путь установки и оба корня; текст кнопки; время клика и первого запроса пакета; объём до паузы; PID shell/backend и результат второго запуска; итог установщика, версия и рабочая запись в B. Проставляем «прошло», «ошибка» или «не проверено». Для промежуточных шагов сохраняем только относящиеся к ним наблюдения. Публичные подписи и обычная учётная запись Windows требуют собственного прогона.
